# Итоговое решение по выпуску 1.5.0-rc1 (кейс DOC-17)

**Решение:** **ОСТАНОВИТЬ ВЫПУСК (NO-GO).**
Кандидат 1.5.0-rc1 не может быть передан в эксплуатацию. Решение основано на обязательных критериях качества и известных результатах тестов.

## 1. Обоснование (почему нельзя выпускать)
1. **Блокировка восстановления (R_RESTORE):** Тест T04 имеет статус `blocked`. Критический сценарий (данные после восстановления соответствуют контрольному набору) не подтвержден. По правилам спецификации, отсутствие подтверждения восстановления блокирует выпуск.
2. **Отсутствие замера производительности (R_PERFORMANCE):** Тест T05 имеет статус `not_run`. Мы не знаем, выдержит ли система 20 операторов и 1000 заявок с p95 ≤ 800 мс. Непроверенный кандидат не может быть принят.
3. **Неподтвержденная целостность пакета:** Отсутствует вычисленный хеш файла `app-1.5.0-rc1.zip`. Имя файла не гарантирует, что пакет не был изменен.

## 2. Минимальные действия для пересмотра решения
Решение может быть пересмотрено только после выполнения следующих условий:

| Условие | Владелец (Ответственный) | Требуемое доказательство |
|---|---|---|
| Организовать restore-target и провести тест восстановления из бэкапа B-1755. | test_owner (student_tester) | Лог восстановления с подтверждением RTO ≤ 20 мин, RPO ≤ 15 мин. |
| Провести нагрузочное тестирование по заданному профилю (20 операторов, 1000 заявок). | test_owner (student_tester) | Отчет с расчетом p95 (ceil(0.95*n)) и долей успеха ≥ 99%. |
| Предоставить вычисленный хеш (SHA-256) для `app-1.5.0-rc1.zip`. | technical_executor (student_engineer) | Значение хеша, совпадающее с эталонным. |

## 3. Ограничения и риски
- **Совместимость данных:** Если после обновления будет включена функция `category_required` и появятся новые записи, возврат на старую версию 1.4.2 потребует согласованного преобразования данных. Автоматический откат к старой копии недопустим.
